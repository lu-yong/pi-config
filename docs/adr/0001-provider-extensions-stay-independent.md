# ADR-0001: Provider 扩展保持独立配置,不提取共享模型目录

- 状态:已接受
- 日期:2026-08-09

## 背景

架构审查(/improve-codebase-architecture)提出候选:micu-provider、cola-provider、anyrouter-provider 三个扩展的模型定义结构高度相似(同款 thinkingLevelMap、contextWindow、分层定价形态),且存在字段差异(如 terra 的 tiers 与 cacheWrite),建议提取共享 model catalog 模块,让各 provider 变成薄列表。

## 决策

不提取。三个 provider 扩展各自独立维护完整的模型定义。

## 理由

模型清单跟随第三方 LLM 提供商,各提供商供应的模型并非一成不变——当前的结构相同只是恰好共同,不是本质共享。目录模块会把独立变化的东西耦合在一起:提供商 A 调价、换模型、改思考档位时,不应需要理解或绕开为 B/C 设计的推导规则,深化后反而让后续改动不方便。看似的"数据漂移"也可能就是各提供商真实的差异定价,统一推导会抹掉这种差异。

## 后果

- 新增 provider 继续按现有文件复制成型——接受这个成本,换取每个文件与提供商公告一一对照、独立可改
- 未来架构审查不应再以「三个 adapter 结构相似/存在漂移」为由重提共享目录候选
- 若某天出现真正的本质共享(例如 pi 的 provider 注册格式变更需要统一迁移),可重新评估本决策
